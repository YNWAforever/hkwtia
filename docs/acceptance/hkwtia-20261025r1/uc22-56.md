## Method and environment

The double gate (`HKWTIA_DB_ACCEPTANCE=1 HKWTIA_DB_TIMING=1`) loads only ignored `.env.acceptance.local` through the existing loader/`verifyAcceptanceTarget` before client construction. Target: project `dark-cake-07139424`, branch `br-restless-pond-a11dpkvd`. AWS `ap-southeast-1` comes from pinned endpoint metadata; compute size is unavailable in that metadata and was not queried or changed. Client: box, Node v22.23.4, Neon serverless WebSocket Pool to the pooled endpoint. Client geography/RTT are not independently established; no network shaping.

The extracted T22-06 bulk helper preserves its draft/community/same-microsecond data shape. Each run inserts 1,000 rows then 9,000 more under its own synthetic applicant: **1,001 / 10,001 owned rows** including the base fixture. Normal `ANALYZE membership_applications` runs after bulk insertion, making fresh fixture statistics an explicit precondition. No planner forcing or compute/settings changes. Independent SQL ordering verifies every timed page; deep cursor follows approximately 90% of the tied UUIDs. Default pages return 20 items with a next cursor, actual adapter LIMIT 21; detail returns the selected owned ID with LIMIT 1.

Per scale/reader: five warmups, then **30 warm and 30 cold samples** (360 timed calls total). Warm uses a reused max-one pool connection. Cold creates a fresh Pool, explicitly connects, releases to that pool, calls the real reader once, then ends the pool. **Cold means a new WebSocket/client connection; the pooled endpoint may reuse PostgreSQL backends, and Neon compute/buffer caches may remain warm.** This is neither suspended-compute nor cold-buffer evidence. Query time covers the full production reader call from Node, excluding explicit connect; total adds connect. Pool construction, serialization, assertions and teardown are excluded. Samples are sequential, not a load test. Percentiles use nearest rank: p50=15th, p95=29th of 30. Payload bytes are UTF-8 serialized repository results, not HTTP/database wire bytes.
