# 行政工時基線：職員操作手冊

本輪程式提供不含正文的計時紀錄、不可變人工比較組及按同類樣本加權的差額報表。本機隔離驗收已通過；兩星期真實營運樣本、比較口徑確認、正式發布及 AI 試點尚未完成。本頁不是發布批准或 ROI 證據。

## 開始收集前

1. 營運負責人與 QA 選定至少兩星期的香港日期、固定比較組參考及工作類別，記下比較口徑和來源。正常人工操作繼續使用現有工作台。
2. 只使用現有案件 ID 及相關 audit／AI run ID。不要抄錄電郵、電話、對話正文、登入連結、cookie 或憑證。比較組 UUID 是計時分組參考，不代表任何角色、會籍或 AI 使用批准。
3. 開發驗收只可用已確認隔離的 DB/Auth 及合成案件。正式收集須在 T16 該能力發布獲授權後；現在可先在受控本機表格計時。

## 每筆計時

在「報表」→「記錄工作計時」填入案件、來源及比較組參考。選擇人工基線或輔助工作，輸入開始／結束時間。日期欄位按操作者裝置時間輸入；儲存成 UTC，報表日期範圍使用香港時間。工作按實際結束時間歸入報表期間；稍後補錄不會把舊工作算到補錄當日。

人手處理、覆核、返工及等候四個互斥類別須等於整段時間。不要把等候算進職員工時，不要同時計入人手和覆核。草稿結果選擇人工工作、採用、編輯或拒絕；這個選項只記錄工時觀察，不批准草稿或發送。

儲存後重複提交同一紀錄不會增加工時。開始新一段工作時按「開始另一筆計時」，填寫新的時間。重開案件保留原案件參考，勾選重開，額外工時另記；案件分母仍只計一次。同一職員的重疊時段及衝突紀錄會被拒絕。

## 每日核對

- 核對案件數、具計時樣本的案件、期間及計時缺失率。零樣本及未知值不可當成零分鐘節省。
- 客服案件涵蓋 bot 及人工接手；其他工作類別目前依已記錄案件補入。沒有完整收集前，不得把樣本外推成全體行政工時。
- 檢查重開、拒絕及返工，保留原 audit/run 關聯。錯誤紀錄不可直接改寫歷史；交 QA 核對後以可追溯更正方式處理。
- 暫時無法儲存時保留不含個人資料的本機計時筆記，稍後用同一紀錄重試，不建立虛假成功收據。

## 固定人工比較組

比較組完成至少兩星期人工期間後，在「報表」→「固定人工比較組」填寫同一比較組 UUID、開始及結束時間（不包括結束時間）。所有人工樣本須屬該期間，結果為「人工工作」。系統只從已關聯紀錄計算同類平均值；不能輸入聲稱節省的數字。

固定操作記錄服務端操作者、期間、樣本數及原紀錄摘要的 SHA-256。併發或重複提交只保留一份；固定後不可補入人工樣本或更改期間。若口徑有錯，交營運負責人與 QA 核對，使用新的比較組並記錄原因，不改寫舊 audit。

輔助工作須使用同一比較組並在人工期間後發生。報表把人工樣本平均值乘以可比較案件數，再減去人手、覆核及返工。重開工時納入原案件，等候獨立列出；負差額保留，無比較樣本則顯示未知。這是樣本差額，不能外推成全體節省或 ROI。公開 AI-Ops 仍保留既有六分鐘「估算」及獨立「尚未測量」狀態。

## 尚待完成

- 營運負責人／QA：真實兩星期人工基線、比較組、覆蓋率和試點口徑。合成資料只驗工程，不作職員績效或 ROI 證據。
- 工程：非客服工作類別的完整自動案件分母仍需隨 T09–T12／T18 工作流程接入。現在明示全部客服及已觀察其他類別的範圍。
- Release owner：T16 逐能力正式發布及試點批准；AI 先 2 staff／每日 50 案件／draft-only 一星期。固定統計比較組本身不批准試點、發送或發布。

## 回復

停止新增計時紀錄，保留既有 audit 與案件歷史。回退相容 app 即可；本項沒有 migration，不刪除 audit 資料。其他會籍、付款、發送及 CMS writer 不受此計時入口控制。
