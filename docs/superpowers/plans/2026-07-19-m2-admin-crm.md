# M2 Admin CRM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the bilingual, staff-only WTIA Admin CRM with Member 360, saved segments and queued campaigns, at-risk operations, event management, approvals, reconciled reports, and deterministic M2 demo data.

**Architecture:** Extend the M1 monolith through actor-first vertical slices. Neon Auth supplies identity, the profile repository resolves global staff roles, application services coordinate transactional repository operations, and localized server-rendered admin pages consume purpose-built DTOs. M2 snapshots campaign recipients but does not send email; M3 owns delivery.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript strict, next-intl, Tailwind CSS, Neon Postgres, Drizzle ORM, Zod, Vitest, Playwright, and Vercel.

## Global Constraints

- Keep the existing M0 and M1 route, billing, webhook, portal, localization, and accessibility behavior green.
- Use `en` and `zh-HK` through `next-intl`; no visible string may be hardcoded in a component or route.
- Server Components are the default. Use client components only for interactions that require browser state.
- Every database repository takes `Actor` first and performs its own authorization check.
- Anonymous users, members, and company admins receive a real 404 for every `/admin/*` page.
- Zod validates every action, route, filter, cursor, and identifier at the application boundary.
- Mutations and their audit records must commit in the same database transaction.
- Never log database URLs, email addresses, phone numbers, note bodies, CSV rows, or campaign recipient variables.
- M2 queues immutable campaign recipients and never imports or calls Resend.
- Use only an isolated `DATABASE_URL_TEST` for migration and integration evidence; never mutate production as a test fixture.
- Use conventional commits and stage only the files named by the active task.
- Run Windows commands with `npm.cmd` and `npx.cmd` in this workspace.

```ts
export function requireAdmin(actor: Actor): asserts actor is AdminActor {
  if (actor.kind !== "staff" && actor.kind !== "exco" && actor.kind !== "superadmin") forbidden();
}

export async function requireAdminActor(): Promise<AdminActor> {
  const actor = await requireActor();
  requireAdmin(actor);
  return actor;
}
```

```ts
export const AT_RISK_SCORE_MAX = 20;
export const AT_RISK_RENEWAL_DAYS = 60;

export function classifyAtRisk(member: AtRiskCandidate, asOf = new Date()): boolean {
  if (member.status !== "active" && member.status !== "past_due") return false;
  if (member.score >= AT_RISK_SCORE_MAX || !member.renewalAt) return false;

}
```
