# M7 Staff CMS Implementation Plan

> **Status:** M7.1, M7.2 and M7.3 are shipped; the boxes below record what was
> delivered. The one outstanding item is upload (Task 3, Step 3), without which
> a developer still has to commit and deploy every image file. Design record:
> `docs/superpowers/specs/2026-08-06-m7-staff-cms-design.md`.

**Goal:** Let WTIA staff publish news and edit marketing page copy without a
developer, by adding two more instances of the admin CRUD stack the repo already
has rather than introducing a CMS as a new system.

**Architecture:** All Neon/Drizzle access stays inside `lib/db/repos`. News
reuses the existing `posts` table scoped to `kind: "news"`. Page copy adds one
`page_copy` table and merges at a single point in `i18n/request.ts`, with the
message bundles as the structural source of truth and the fallback.

**Tech Stack:** Next.js App Router, React Server Components, TypeScript strict,
next-intl, Drizzle ORM with Neon Postgres, Zod, Vitest, Playwright.

## Global Constraints

- Develop on `claude/code-review-icazin`; never point fixture or seed commands
  at Production — use an isolated `DATABASE_URL_TEST` per AGENTS.md.
- Every repository method takes an `Actor` first and calls `requireAdmin` before
  parsing and before opening a connection; denial becomes `notFound()`.
- Every mutation writes its audit row inside the same transaction.
- All visible copy lives in `messages/en.json` and `messages/zh-HK.json`.
- News owns `kind: "news"` only. `kind: "page"` stays the board reporter's and
  `kind: "buildlog"` stays seed/agent-owned; neither becomes editable.
- The `SafeStructuredContent` grammar is not extended. Each addition (images,
  external links, italics, ordered lists, code blocks) is a new XSS surface in
  the one component that renders untrusted body content and needs its own
  decision with its own hostile-input tests.
- Page-copy overrides may only replace an existing English leaf string, and the
  editable namespace set is a hard-coded allowlist in code.
- Preserve prior migrations; add only sequential `drizzle/0016_m7_page_copy.sql`
  plus its generated snapshot and journal entry.

### Task 3: Media (M7.3) — shipped, with Step 2 dropped

**Files:**
- Create: `lib/media/url.ts`, `lib/db/repos/media.ts`, `lib/admin/media-{actions,action-core,form-input}.ts`,
  `components/admin/media-form.tsx`, `app/[locale]/(admin)/admin/media/{page,[id]/page}.tsx`,
  `drizzle/0017_m7_media.sql`
- Modify: `lib/db/schema-core.ts`, `lib/showcase/contracts.ts`, `lib/db/repos/showcase.ts`,
  `lib/admin/showcase-actions.ts`, `components/marketing/showcase-{card,detail}.tsx`,
  `components/admin/showcase-review-table.tsx`, `next.config.ts`, `scripts/seed-m5.ts`, both bundles

- [x] **Step 1:** Media registry — `url`, `altEn`, `altZh`, `registeredByProfileId`, timestamps — with an
  admin section to register and browse images. `width`/`height` were dropped: nothing consumes them
  (`page-hero` uses `fill`, the other two hardcode), and with no upload they could only be typed by hand,
  where a wrong value silently distorts the image.
- [x] **Step 2 — DROPPED.** `images.remotePatterns` is not added, and `next.config.ts` gains no `images`
  key at all. The defaults are already the safe values, and an allowlist cannot constrain a host you do
  not own: Next's optimizer checks `remotePatterns` once while parsing the URL
  (`image-optimizer.js:597`) and then follows up to three redirects without re-checking
  (`:958-969`). The registry is own-origin only instead, so there is no remote host to allowlist.
- [x] **Step 2′ (replaces it):** an image-scoped `Content-Security-Policy` — `img-src 'self' data:` and
  nothing else, so it carries none of a `script-src`'s white-screen risk. Verified against a production
  server: header present, pages render, scripts intact.
- [ ] **Step 3 — not started.** `@vercel/blob` upload. Re-scoped from *"only if step 1 proves
  insufficient"* to **required**: step 1 is insufficient by construction. There is no ingestion path in
  the repo, so every registry row must point at a file a developer committed and deployed. This
  milestone makes images render *safely*; it does not take the engineer out of the loop.
- [x] **Added, not in the original plan — a live security fix.** `isSafeLogoReference` had two working
  bypasses: `"/\\evil.example.com/x.png"` and an interior tab, LF or CR both passed the `/` prefix test
  and then resolved to a foreign host, because the WHATWG parser maps `\` to `/` and strips those
  control characters while zod's `.trim()` only touches the ends. Member-reachable, and it reached
  production HTML as a schema.org `image`. Fixed with a shared obfuscation primitive.
- [x] **Added — actually rendering the logo.** Without it the registry would have had zero consumers.
  Showcase listings gained a nullable `logo_media_id` FK *beside* the existing free-text column, which
  stays persisted and validated for the JSON-LD sink but is never rendered. Staff attach the registry
  entry during review; the member form is unchanged.
- [x] **Added — the review table shows the picture.** Blind approval was tolerable while the value was
  invisible metadata; it is not once it is an image published under the association's brand.
- [x] **Added — render-policy guards.** A discovery test forbids raw `<img>` and `unoptimized` across
  `app/` and `components/`, both being escape hatches that move the fetch into the visitor's browser and
  leak their IP to whatever host is in the `src`.
- [x] **Added — the seed's three dangling `/images/showcase/*.svg` paths** pointed at files git has never
  tracked, and are now `null`.
- [x] **Added — the admin auth guard test now discovers routes.** Its hand-maintained allowlist had
  silently omitted `/admin/listings-review`, `/admin/cohorts`, `/admin/automations` and the admin index,
  so those were unguarded by the test that exists to guard them.

## Verification

Full AGENTS.md gate set after each milestone:

```sh
npm test && npm run lint && npm run typecheck && npm run audit:strings && npm run build
```

Milestone-specific checks, all covered by the suite:

- **M7.1** — a member and an anonymous actor get `FORBIDDEN` before the
  connection is opened; a published post appears on `/news`, at its slug and in
  the sitemap while a draft appears in none; a build log is not editable through
  the news UI; a duplicate slug is a field error, not a generic failure;
  publishing writes its audit row in the same transaction.
- **M7.2** — `applyPageCopy` replaces `Privacy.sections.0.body.0` and leaves
  `sections` an array; unknown key paths, out-of-scope namespaces and
  placeholder mismatches are each rejected; `getRequestConfig` returns the
  bundle unchanged when the repository throws and `npm run build` succeeds with
  no `DATABASE_URL`; every in-scope namespace maps to a real public route; an
  override changes one locale while the other still shows its bundle value.
- **M7.3** — `javascript:`, `data:`, protocol-relative, backslash- and control-character-obfuscated,
  query-string and `.svg` URLs are all rejected by the media validator; a registered site-relative PNG
  renders on the showcase card and detail page with its locale-correct alt text; a member and an
  anonymous actor are refused before a database connection is opened; no remote image host is
  configured, and the optimizer returns 400 for one.

Remaining end-to-end, against an isolated `DATABASE_URL_TEST` — never point
fixture commands at production: sign in as staff, publish a news post, confirm
it on `/news` in both locales, edit a page-copy string, and confirm the public
page reflects it after revalidation.

## Known follow-ups

- The Chinese bundle still carries `"_review": true`; the whole translation set
  is pending human review, and page-copy overrides do not change that.
- The privacy notice needs legal review and carries no "last reviewed" date.
- Programme details, the chairman's message, committee names and remits, About
  copy, and the first news posts and events are all blocked on facts the
  association has to supply. The tooling to enter them now exists.
- `approvals.decide` records a sign-off but has **no effect executor** — nothing
  acts on `status = 'approved'`. M7 publishes directly, which is fine, but any
  future approval-gated publishing needs the effect built, not just an approval
  type registered.
