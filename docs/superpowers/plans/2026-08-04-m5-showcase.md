# M5 Showcase Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the WTIA Showcase from company listing submission through staff publication, public bilingual discovery/detail pages, request-intro leads, sitemap/JSON-LD, premium ordering, and debounced views.

**Architecture:** A dedicated `showcase_listings` relational model and `leads` table are exposed through actor-scoped repository methods in `lib/db/repos/showcase.ts`. Shared Zod contracts and public projections live in `lib/showcase/contracts.ts`; Next.js server pages/actions consume those seams so public reads cannot expose workflow/private fields.

**Tech Stack:** Next.js 16 App Router, React 19 server components/actions, TypeScript, Zod, Drizzle ORM/Postgres, Vitest, Testing Library, Playwright, next-intl, existing Resend/test email transport.

## Global Constraints

- Preserve the bilingual `en` and `zh-HK` locales and keep their message leaf keys in parity.
- Keep public listing pages server-rendered and indexable; do not move database filtering into a client-only data fetch.
- Enforce actor authorization inside repositories before every member/staff mutation.
- Public queries may return only `published` listings and must omit reviewer, workflow, lead, email, and internal ID fields from public projections/JSON-LD.
- Use the existing process-local rate limiter and configured/test email transport; never call a live provider or modify Production/shared environments in tests.
- Keep the `eab619c` M4C behavior and all existing tests green; unrelated baseline failures must remain separately identified.
- Use TDD: every production behavior below starts with a focused failing test and is re-run green before the next behavior.
